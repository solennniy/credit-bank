# Кредитный кабинет · Альфа-Хак

Работающий **фронтенд**, без базы данных, серверного API и настоящей авторизации. Оформление перенесено из макетов команды в Figma. Клиент и банк работают с общими демоданными этого браузера.

## Запуск

Нужен Node.js 22 или новее (проверено на 24.18.1). Сторонних пакетов и установки зависимостей нет.

```sh
npm start
```

Открыть http://localhost:4173. Альтернатива: `docker compose up --build`. Локальный сервер раздаёт только статические файлы; прикладного бэкенда здесь нет.

## Что работает

- Стартовая страница в стиле страницы кредита из Figma.
- Мои заявки, черновик, ручное сохранение, подтверждение автоданных, проверка комплектности.
- Добавление PDF: проверяются расширение, MIME, размер и сигнатура. **Сохраняются только метаданные, содержимое файла не хранится.**
- Отправка, рассмотрение банком, запрос/замена документа, повторная отправка.
- Одобрение, отказ с причиной, предложение другой суммы/срока, принятие версии условий.
- Демонстрационная выдача, отзыв заявки, фильтр списка, истории клиента и банка.
- Подтверждение важных действий и защита демоадаптера от неверных переходов/устаревшей версии заявки.
- Данные переживают перезагрузку страницы через localStorage; можно экспортировать и сбросить демонстрацию.

## Пройти основной сценарий

1. Нажать «Подобрать финансирование». Заполнить форму, подтвердить данные, сохранить.
2. Выбрать настоящий PDF с синтетическими сведениями, сохранить и отправить заявку.
3. Переключить демороль на сотрудника банка. Взять заявку на рассмотрение.
4. Запросить документ с причиной. Переключиться на клиента, добавить PDF нужного типа и отправить дополнение.
5. В банке снова начать рассмотрение, предложить меньшую сумму или одобрить.
6. Клиент сравнивает условия и принимает актуальную версию. Банк моделирует выдачу.
7. Перезагрузить страницу: данные и история остаются. Проверить отказ, отзыв и неподходящий файл отдельными заявками.

Демороли — **переключение представлений, не контроль доступа**. Весь набор данных доступен в браузере. Не использовать реальные персональные и финансовые сведения. Между разными устройствами данные не синхронизируются. Одновременная запись из разных вкладок полностью не сериализуется; сервер должен обеспечить транзакции и идемпотентность.

## Для бэкендера

Заменить `src/demo-api.js` HTTP-адаптером с теми же методами. Экраны не обращаются к localStorage напрямую. Контракт, обязательные серверные проверки и границы: [docs/API.md](docs/API.md).

## Проверки

```sh
npm run check
npm test
```

В тестах проверяются основной процесс, запрос документов, версии предложений, неверные переходы, недоступные демороли и повторы отправки. Это не проверка безопасности реального сервера: он не реализован.

## Дизайн и ограничения

Figma: https://www.figma.com/design/wyNhLChU5ZpudZpuuE5RDX/Alfa

Реализованы основные состояния, а не все независимые кадры Figma как отдельные страницы. Интерфейс адаптирован для узких экранов. Шрифт Inter из макетов может быть заменён браузерным Arial при отсутствии установленного Inter; фирменный Alfa Interface Sans не поставляется. Ставки, полная стоимость, подписание, реальные проверки и банковские переводы отсутствуют. Пустые данные не заменяются выдуманными одобрениями.

Облачный деплой не выполнен. Для сдачи зафиксировать commit SHA или тег до дедлайна; при приватном репозитории дать доступ жюри `alfa-hack-2026` согласно заданию. Дизайн содержит синтетические исследовательские сценарии, не результаты реальных интервью.
